### 1.2 Seven-Category Forensic Classification Legend
Every feature, route, and module in OmniFlow OS is classified strictly into one of the following seven forensic categories:
1. **`[CAT-1] Implemented & Verified`:** Production-grade code exists in the repository and is directly verified by automated unit, integration, emulator, or security tests (`server/test/run-audit.ts` / `server/test/firestore-rules-audit.ts`).
2. **`[CAT-2] Partially Implemented`:** Real code and logic exist, but external provider wiring, persistence, or edge-case security is incomplete.
3. **`[CAT-3] UI-Only / Interactive Prototype`:** Rich frontend interface and state interactions exist, or backend returns static/blueprint structures without live operational execution.
4. **`[CAT-4] Simulation / Mock`:** Code intentionally simulates external telecom, social, or hardware behavior using timers, synthetic transcripts, or local browser APIs without talking to a real external provider.
5. **`[CAT-5] Documented Only (Unimplemented in Code)`:** Described in `/docs/*.md` or TypeScript `interface` contracts (`contracts.ts`), but has zero active runtime class implementation.
6. **`[CAT-6] Non-Existent (Greenfield Gap)`:** Not present in code, schema, or UI; must be architected and built in future phases.
7. **`[CAT-7] Conflicting Evidence / Split-Brain`:** Multiple incompatible implementations or schemas exist simultaneously across different layers of the codebase.

## 4. Critical Architectural Contradictions & Split-Brain Risks (`[CAT-7]`)

### 4.1 Contradiction #1: Data Persistence Status (Remediated in Runtime Store in Phase P.1; Cloud SQL Still Unwired)
1. **Unified Runtime JSON File Store (`server/db/store.ts` — Phase P.1 Completed):** All 16 operational collections (`organizations`, `users`, `customers`, `conversations`, `messages`, `tickets`, `calls`, `agents`, `knowledgeDocuments`, `shifts`, `automationRules`, `qaEvaluations`, `channelConfigs`, `recommendations`, `coachingPlans`, `macros`, `teamQaFeedback`, `connectedDevices`) plus `crossDeviceSyncEvents` and `auditEvents` are now consolidated inside `DatabaseStore` (`IDataStore`) with strict `organizationId` isolation, atomic temp-file-and-rename JSON persistence to `/tmp/omniflow-data/db_state.json`, and explicit disk-failure rollback (`DISK_PERSISTENCE_READ_FAILED` / `DISK_PERSISTENCE_WRITE_FAILED`). **Residual Risk:** `/tmp/omniflow-data/db_state.json` is local container filesystem persistence and is NOT durable cloud infrastructure storage across stateless container replacements.
2. **Previously Unpersisted Module Maps in `server/api/router.ts` (RESOLVED in Phase P.1):** All 6 module-scoped structures (`memoryChannelConfigs`, `memoryRecommendations`, `memoryCoachingPlans`, `memoryMacros`, `teamQaFeedbackLedger`, `connectedDevicesRegistry` + `crossDeviceSyncLedger`) have been removed from `server/api/router.ts` and migrated into `server/db/store.ts` and `server/db/seed.ts`, verified by automated tests `P1-01`..`P1-09`.
3. **Cloud SQL PostgreSQL + Drizzle (`src/db/schema.ts` & `src/db/index.ts`):** `src/db/schema.ts` defines 11 tables, but `src/db/index.ts` is not imported or called by any runtime route. Runtime data operations do not read or write PostgreSQL yet.
4. **Client-Side Firestore (`src/lib/firestoreService.ts`):** Syncs `tickets` and `conversations` from the browser when authenticated with Firebase Auth.

### 4.2 Contradiction #2: External Webhook Authentication Block (`router.ts` Global Auth vs Webhook Ingress)
- **Evidence:** `apiRouter.use(authenticateApiRequest)` is registered globally before `/integrations/:channel/webhook`.
- **Impact:** External webhook calls from Meta/Telegram/Twilio without an OmniFlow session token receive `HTTP 401` until public HMAC-verified webhook ingress is extracted in Phase P.2/S.

### 4.3 Contradiction #3: Organization ID Dual-Naming (`org-madar-enterprise-001` vs `org-madar-001`)
- **Forensic Correction & Exact Inventory:**
  - `server/db/seed.ts:10`: `export const DEMO_ORG_ID: UUID = 'org-madar-enterprise-001';` (Active runtime backend & seed default organization ID)
  - `firestore.rules:66, 311` & `DRAFT_firestore.rules:66, 311`: `orgId == 'org-madar-001'` (`isDesignatedBootstrapOrg` rule)
  - `src/lib/firestoreService.ts:112, 115, 160, 163, 207, 210, 227, 230, 248`: `'org-madar-enterprise-001'`, whereas `src/lib/firestoreService.ts:254` uses `'org-madar-001'`
  - `src/App.tsx:263`: `currentUser?.organizationId || 'org-madar-001'`
- **Phase P.1 Safeguard:** Per Phase P.1 engineering controls, blind global Find & Replace between `org-madar-enterprise-001` and `org-madar-001` was intentionally halted to prevent breaking the SHA-256 `auditEvents` hash chain, deployed `firestore.rules`, or the 39 JVM Firestore Emulator tests, and is documented with a dedicated human-approved migration plan.
